# SEC013 local inventory and provisioning plan

This is the proposed next preparation batch. Runtime storage selection and quota activation remain outside its scope. No existing storage has been scanned, changed or deleted.

## Complete namespace accounting

Run inventory only while all writers to the local root and relevant ownership references are quiesced under a trusted maintenance barrier. A filesystem traversal cannot prove completeness if the old unmetered writers are still active. The utility accepts only a previously bound local namespace/root, rejects active adapter path locks or uncertain operations, and never changes namespace binding to make an import succeed. S3 remains gated.

Persist an inventory epoch, root identity, maintenance token, phase and checkpoint in a new table; persist directory work/checkpoints separately so a very wide tree cannot accumulate an unbounded queue in memory. No readiness state is set during discovery or import. Use opendir streams in bounded batches, not readdir arrays. Checkpoints record directory identity/timestamps, offset and a rolling prefix digest. On resume, rescan and verify the skipped prefix; changed ordering/identity or contents fails closed. A final verification pass detects disappeared/changed/imported objects and incomplete directory work. Failed scans retain all imported bytes and the gate, and can resume only the same verified epoch/barrier.

Every regular file is measured through no-follow descriptors and receives a durable private fingerprint. Symlink, hardlink, permission, unsupported file, malformed metadata and traversal errors fail the epoch instead of skipping bytes. Do not follow a link outside the root. Directory checkpoints, exact object paths, hashes and bearer-like cloud slot filenames remain private database/filesystem metadata; status and test reports expose only counters, phases and sanitized error codes.

Import payload objects with deterministic epoch/path generation identities and idempotent ledger object rows. Repeated import does not double-charge. Create adapter generation manifests only for confirmed payload objects, without rewriting payload content. Unknown/orphan/temp objects remain owned by `system:legacy-unattributed` with category `legacy-unattributed`; they are not automatically removed, released, adopted by another user or made writable through a guessed principal. Adapter-private metadata is inventoried separately without creating manifests for its own manifests.

The metadata pass counts all manifest, intent, tombstone, namespace-binding and leftover temporary bytes and object counts under a dedicated system account. It has finite byte/file bounds and fails if a bound is exceeded. Inventory checkpoints/DB rows also need bounded batch sizes and total admission. Limits must cover the metadata generated by import before readiness can be considered. Payload size alone does not establish complete accounting. Unknown retained adapter operations require explicit recovery, not age-based release.

End this preparation utility at `inventory-complete`, not `ready`. That state documents the complete epoch while preserving the existing ledger admission gate. Full activation still requires bounded metadata lifecycle, all-writer ownership/admission, config invalidation, serving denial for private metadata and reviewed admin integration. Lower limits than existing usage must preserve files and block growth.

## Trustworthy ownership

Resolve only exact persisted references in bounded queries. CloudAttachment uploadFilename/user_id identifies a staged object's logical uploader. Posted attachment attribution requires matching channel, exact filename and either attachment or legacy message path identity, joined to its persisted Message; webhook/application identity takes precedence over the apparent message author. User current avatar/banner hashes can identify their exact objects. Additional guild-member/current webhook/application references can identify their corresponding logical asset principal when their persisted exact reference and principal exist.

Historical hashes, absent references, conflicting owners and arbitrary path prefixes do not establish ownership. Guild/channel IDs do not identify an uploader; a guild's current owner must not inherit every old asset. Managed store/badge art and upstream mirror namespaces remain distinct categories, each charged to the finite instance total; cache additionally has its cache sub-budget. System exports and other unsupported reference families remain explicitly unattributed until their trusted resolver is implemented. Conservative incompleteness cannot exempt a file from instance usage.

Trusted principal provisioning occurs only after a completed epoch, checks the current persisted user/webhook/application identity and uses a fixed server-owned category/key. It must not accept a caller-selected string as ownership proof. Provisioning inserts a zero-usage account only if none exists; it cannot overwrite counters, reassign unknown objects, clear reservations or promote the instance to ready. Existing imported accounts retain their totals. Operator-managed system principals use a closed allowlist.

## Migration and admin acceptance

The new PostgreSQL migration must be idempotent, have a unique timestamp after existing migrations, and define bounded inventory run/work records independently of user/message cascades. Tests apply it twice to a fresh temporary schema, exercise transactional rollback and drop only that test-created schema. No existing table/data reset is permitted.

The later administrator integration must use existing operator rights and show phase, used/reserved bytes, object counts, attributed/unattributed/cache/metadata totals, last complete epoch and sanitized failure codes. It must require a maintenance barrier for initial scan, permit checkpointed resume, and refuse activation on incomplete scans, metadata excess, unresolved operations or unmetered writers. An interrupted scan cannot produce a zero-usage dashboard or a usable quota. Ownership reassignment, physical deletion and cache eviction are separate explicit operations, not inventory side effects. Reconciliation must never release bytes because a database reference disappeared.

Required isolated evidence: wide-directory streaming remains bounded; crash at each checkpoint/import boundary resumes without duplicate charge; unknown objects and historical hashes remain charged; cross-user conflicting references cannot grant ownership; metadata/tombstones/temp files count; every filesystem/DB failure preserves the gate; source changes invalidate resume; completed inventory still rejects ledger writes; post-epoch provisioning verifies persisted identities and preserves counters; no payload bytes or existing files are changed or deleted. Final live acceptance belongs to the coordinated activation batch, not this utility.
