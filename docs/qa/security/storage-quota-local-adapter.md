# SEC013 local adapter preparation

`FileQuotaStorageAdapter` implements the separate quota adapter contract. It is not selected by Storage.ts, does not replace existing FileStorage behavior, and has never been pointed at live storage. Its namespace and root are explicit constructor inputs. A durable root binding prevents constructing another namespace over the same files to reset attribution; changing it requires reviewed inventory migration. Existing files without matching generation metadata are rejected, never adopted, overwritten or deleted. There is no inventory import/reset method in this batch.

Each content path has a durable generation manifest under the reserved `.storage-quota/objects` namespace. Each operation has an intent under `.storage-quota/operations`, with the prior generation and the prepared output fingerprint. Directory permissions are 0700 and metadata/temp file permissions are 0600. Content paths cannot enter that namespace. Later serving integration must explicitly deny that namespace, and inventory must handle it separately from user content.

Fingerprints contain actual file size, device/inode identity and SHA256, using no-follow file descriptors. Replacement streams through the existing EXIF transformer into a distinct temporary file; a transform bound rejects output exceeding the reserved maximum. The temporary file and intent are synced before atomic rename, and parent directories/metadata are synced afterward. The old destination remains present until rename. An error after rename cannot prove unchanged; replay recognizes the prepared fingerprint and repairs generation metadata without rewriting content.

Clone validates the source generation, enforces its measured size against the destination reservation, streams a distinct copy without reapplying EXIF changes, and rechecks source/output fingerprints. Source and destination use independent files and remain independently charged by the ledger. Zero-byte objects retain generations. The adapter returns measured content bytes; it does not infer physical block-sharing discounts.

Deletion verifies the requested generation/content, marks no quota counters itself, removes the object, syncs its directory, verifies absence, and records a durable generation tombstone. Failure before or after physical unlink remains retryable. The tombstone permits the same removal to succeed again if the later database release fails, while a subsequent write of another generation prevents an old delete from removing it. Permission/I/O failures are exceptions, never interpreted through existing Storage.get/exists fallbacks.

Per-path mkdir locks serialize adapter operations across processes. Clone acquires source and destination locks in sorted order. Locks are never stolen based on age; a crashed process leaves a conservative recovery gate. `unchanged` requires a matching durable intent, no surviving staging file and an exact match with the prior fingerprint or confirmed absence for a new object. Missing intent, changed content, invalid metadata and uncertain cleanup cannot prove release safe.

The root and its metadata must be controlled exclusively by this adapter/inventory tools once enabled. Existing symlinks, hardlinks, traversal and reserved paths are rejected. Node's filesystem APIs do not offer an atomic descriptor-relative rename/unlink equivalent to openat2; this implementation cannot protect against a hostile local process racing ancestor-directory swaps. It rechecks content before replacement/deletion, but ordinary path checks do not establish a hostile-filesystem security boundary. Do not enable it on a writable shared filesystem with untrusted local writers.

Remaining enablement work includes all trusted ownership propagation/writers; a reviewed inventory import; conservative crash-lock and operation recovery; bounded completed-intent/tombstone retention; accounting/reserving adapter sidecar and temporary overhead; explicit metadata serving denial; cross-worker config invalidation; admin controls; and live disposable quota proofs. This batch preserves durable intents rather than pruning them unsafely. Those metadata files and ledger operation rows must be bounded before claiming aggregate storage is fixed. S3 remains unsupported by this adapter and requires a positively verified version policy/version-aware implementation separately.

Validation uses only uniquely named directories created under the OS temporary directory and removes only those fixtures. `node --test scripts/tests/file-quota-storage.test.cjs` exercises actual EXIF output measurement, bounded transforms and clones, atomic replacement, injected pre/post-rename failures, durable replay, deletion failure/retry, tamper and generation checks, unknown files, symlink/hardlink/traversal rejection, poisoned temporary metadata, late tamper before deletion, competing adapters, crash locks zero-byte files and namespace-binding rejection. Existing runtime storage/provider behavior is unchanged.
